# Neovim Configuration History

Record of the editor config evolution in this repo. Useful when deciding whether to refactor again, and to avoid re-litigating settled decisions.

## Current state (April 2026, post-vim.pack migration)

- Base: **kickstart.nvim-derived, migrated to Neovim 0.12's built-in `vim.pack`**.
- Plugin manager: `vim.pack` (native, experimental but stable for daily use).
- LSP: `nvim-lspconfig` + Mason for server installers. Python, Go, Lua configured; others available via Mason.
- Completion: `blink.cmp` with `LuaSnip` as snippet backend.
- Layout:
  ```
  dot_config/nvim/
  ├── init.lua                  single-file config (383 lines)
  ├── kickstart/
  │   └── health.lua            :checkhealth definitions
  ├── custom/
  │   └── plugins/init.lua      extension point for user plugins
  └── nvim-pack-lock.json       generated by vim.pack; commit this
  ```

## Evolution

### Phase 1 — ThePrimeagen's config (deprecated)

Initial attempt at a 100% copy of ThePrimeagen's setup. Too complex to maintain — too many bespoke keymaps and plugin combinations. Deleted April 2026 as part of the 0.12 migration.

### Phase 2 — kickstart.nvim

Switched to kickstart.nvim for readability and simplicity. Single-file, documented inline, designed to be edited. Decision was correct.

Active plugin list (11) at the end of this phase:
- guess-indent.nvim, gitsigns.nvim, which-key.nvim
- telescope.nvim + plenary + fzf-native + ui-select + web-devicons
- nvim-lspconfig + mason.nvim + mason-tool-installer + fidget.nvim
- blink.cmp + LuaSnip
- conform.nvim
- tokyonight.nvim
- todo-comments.nvim
- mini.nvim (ai, surround, statusline)
- nvim-treesitter

### Phase 3 — Neovim 0.12 + vim.pack (April 2026, current)

**Scope:** Replace `lazy.nvim` with the built-in `vim.pack`. Keep every feature and plugin from Phase 2.

**Why this path (Path B in the planning discussion):** The kickstart structure is already readable and sane. Swapping the plugin manager is a contained refactor. Greenfield rewrite (Path C) would save more lines but means re-deciding every keymap and plugin choice — not worth the time when kickstart's defaults are already good.

**What was kept verbatim:**
- All 11 active plugins (same URLs, same behaviors)
- All keymaps (LSP, telescope, window navigation, diagnostic, terminal exit)
- The full LSP `LspAttach` autocmd (rename, code action, declaration, reference highlighting, inlay hints toggle)
- The telescope LSP `LspAttach` autocmd (grr/gri/grd/gO/gW/grt)
- `vim.diagnostic.config()` settings
- `vim.schedule()` deferred clipboard setup (avoids slowing startup)
- lua_ls's special runtime/workspace config
- Conform's format-on-save with c/cpp exclusion

**What was added:**
- **Version guard** at the top (`vim.fn.has('nvim-0.12') == 0` → error). Fails fast on old nvim.
- **`PackChanged` autocmd** replacing lazy.nvim's `build = 'make'` pattern. Runs `make` in telescope-fzf-native's install directory on install/update. Must be defined *before* `vim.pack.add()` to catch install events.

**What was removed:**
- lazy.nvim bootstrap block (~14 lines)
- Lazy's `priority = 1000` for colorscheme (replaced by list-order in vim.pack.add)
- ~200 lines of kickstart tutorial comments (kept substantive explanatory comments only)
- All 6 unused kickstart/plugins/*.lua (autopairs, debug, gitsigns-extras, indent_line, lint, neo-tree). These were always commented-out; deleted rather than kept as references. Pull from upstream kickstart source if needed later.
- Stale `lua/theprimeagen/` directory (nothing required it)

## Known trade-offs of vim.pack vs lazy.nvim

| Concern | vim.pack behavior | Mitigation |
|---|---|---|
| Experimental marker | Officially experimental in 0.12 docs. Breaking API changes possible in 0.13. | Accept the risk. Migration from vim.pack to whatever replaces it will be smaller than kickstart→vim.pack was. |
| No lazy-loading | All plugins load at startup. | With 19 packages total, startup is still ~150–200ms on a modern machine. Not an issue unless growing to 50+ plugins. |
| No declarative `build = 'make'` | Handled via `PackChanged` autocmd (see init.lua). | Works. Slightly less ergonomic than lazy's per-plugin `build` key. |
| Lockfile location | `~/.config/nvim/nvim-pack-lock.json` (inside config dir, not plugin dir). | Commit the lockfile. chezmoi will pick it up automatically since it's under `dot_config/nvim/`. |
| Plugin commands (`:Lazy`, etc.) | No UI. Use `vim.pack.update()` and `:h vim.pack` directly. | `:checkhealth vim.pack` shows plugin status. |

## Decisions worth preserving

- **No vim distros** (LazyVim, AstroNvim, LunarVim). Distros optimize for "looks impressive" not "I understand every line."
- **Keep Mason** for auto-installing LSPs. The "just works" experience is worth 2 plugins over maintaining a parallel system LSP install list.
- **Keep blink.cmp + LuaSnip** despite nvim 0.12's built-in `vim.lsp.completion`. The native version is minimal; blink.cmp has richer UX (ghost text, path completion, fuzzy matching) for a small config.
- **Keep conform.nvim** over LSP-only formatting. LSP formatters don't cover external tools like `stylua`, `black`, `prettier`, `goimports`.
- **Two-Brewfile approach for nvim runtime deps.** `brew/linux/`, `brew/macos/`, and `brew/devcontainer/` all install `neovim`, `tree-sitter`, `luarocks`, `ripgrep`, `fd`, `fzf`. Duplication is intentional.
- **`tree-sitter-cli` via npm in `dot_zshrc`** is a belt-and-suspenders fallback.

## First-time setup on a fresh machine

After `chezmoi apply` places the new `init.lua`:

1. Launch nvim. `vim.pack` clones all 19 plugins into `~/.local/share/nvim/site/pack/core/opt/` on first start.
2. The `PackChanged` autocmd fires for `telescope-fzf-native.nvim` and runs `make` automatically. This requires `make` + a C compiler on the system. Both are in the Homebrew formulas, but on a bare Linux install make sure `build-essential` / `@development-tools` / `base-devel` is present (see `docs/linux.md`).
3. Mason installs the configured LSP binaries on first launch (pyright, gopls, lua-language-server, etc.). Watch progress with `:Mason`.
4. Treesitter parsers for the configured filetypes install on demand via `require('nvim-treesitter').install()`.

Run `:checkhealth` after first launch to confirm everything is wired up.

## Future considerations (not doing now)

- **Consider dropping Mason** and installing LSPs via Brewfile or system package manager. Would remove 2 plugins and one async install path. Revisit if Mason causes friction on Fedora Atomic.
- **Consider replacing `blink.cmp` with native `vim.lsp.completion`** in nvim 0.13 or later if the native version gains ghost text and path completion.
- **Consider replacing `mini.statusline` with native `'statuscolumn'`/`'statusline'` config** if it grows complex custom sections.
- **Consider pinning plugin versions** in `vim.pack.add()` specs (e.g., `{ src = '...', version = 'v1.2.3' }`) once the config is truly stable. Currently uses latest from default branch, lockfile provides reproducibility between explicit updates.
